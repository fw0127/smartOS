# smartOs — 最小调度核心(设计阶段)

> 状态:**v0.5.1**:调度核心 + 可选的环形缓冲/零拷贝/监控模块、配置生成器、平台契约一致性套件、随机状态机测试;下一步是第一个真实平台(v0.6)  ·  许可证:MPL-2.0
> 设计来源:对一个既有嵌入式固件执行模型的抽象提炼

## 一句话定位

smartOs 是一个**与硬件无关**的**协作式(非抢占)、运行到完成、全静态配置**的调度核心。
它只依赖一组抽象的平台能力(时间、互斥、等待、健康信号、安全停机),可以运行在任何裸机 MCU、RTOS 线程,或 PC 主机进程中。

## 快速开始

```bash
make test        # 16/32/64 位计数宽度 + 5 种模块组合下运行全部主机测试(含随机状态机测试)
make test-san    # 同上,开启 AddressSanitizer + UBSan
make test-thread # 线程平台上的并发测试(真实时间,线程模拟中断)
make test-tsan   # 同上,开启 ThreadSanitizer
make test-gen    # 生成器单元测试 + 由描述文件生成的流水线示例端到端运行
make test-contract # 平台契约一致性套件(虚拟时间平台 + 线程平台)
make example     # 构建手写配置示例,运行 ./build/manual_cfg
make all         # 以上全部(不含 sanitizer 变体)
```

把内核集成到其他构建系统:见 [kernel.mk](kernel.mk) 中的源文件与头文件目录清单,或使用 [CMakeLists.txt](CMakeLists.txt) 中的 `smartos_add_kernel()`。移植到新平台:见 [附录 A](docs/A_附录_平台适配示例.md)。

## 设计原则

1. **内核不认识硬件**:内核源码中不出现任何芯片、外设、寄存器、编译器扩展或通信协议的名字。
2. **依赖能力,不依赖实现**:内核向下只依赖"平台能力契约"(见 05 篇),每项能力只规定语义和性质,不规定如何实现。
3. **时间是抽象量**:内核只处理"单调递增、自然回绕的计数值"及其速率,不假设时钟来源、位宽以外的任何物理属性。
4. **业务无关**:内核不知道任务在做什么(通信、控制、诊断……),只知道它们的触发条件、优先级和健康状况。
5. **可在主机上完整验证**:因为不依赖硬件,所有调度行为都能用虚拟时间在 PC 上精确复现。

## 设计目标

| 目标 | 量化指标 |
|---|---|
| 小 | 目标代码体积待 v0.5 在真实平台上实测确定(见 05 篇待决问题);每任务运行时状态 ≤ 32 字节(按 32 位计数) |
| 确定性 | 无堆、无抢占、单执行流;最坏响应时间可静态计算 |
| 可移植 | 平台适配 = 实现 7 个函数 + 2 个常量 |
| 可测试 | 主机端虚拟时间下的场景测试可逐 tick 复现 |

## 已定的关键决策

| 编号 | 决定 |
|---|---|
| D1 | 就绪位图 + 最低置位查找(常数时间,内核自带可移植实现) |
| D2 | 内核提供单生产者/单消费者环形缓冲,可绑定消费者事件 |
| D3 | 任务连续 `AGAIN` 达到上限后让出一次 |
| D4 | 用 TOML 描述文件 + 生成器产生配置,构建期检查 |
| D5 | 钩子采用函数指针表 |
| D6 | 独立成库;真实平台适配由使用方实现 |
| D7 | 许可证 MPL-2.0;生成器输出归使用方 |
| D8 | 环形缓冲同时提供按值和原地访问(零拷贝)两种接口 |
| D9 | 生成器先以源码随仓库提供 |
| D10 | 提供非阻塞的 `sos_poll`,可嵌入既有主循环 |
| D11 | 环形缓冲记录归属任务;任务停止/重启时自动放弃其未完成的原地操作 |
| D12 | 环形缓冲、零拷贝、监控为编译期可选模块 |
| D13 | 让出只有在较低任务或空闲槽真正运行后才算给出 |
| D14 | ABI 版本负责兼容;摘要用于头文件与表格配对检查 |
| D15 | 环形缓冲溢出钩子推迟到调度器上下文调用 |

详见 [05 篇第 4 节](docs/05_平台契约与路线图.md)。

## 非目标(第一版不做)

- 抢占式调度、多栈、上下文切换
- 动态创建/删除任务、动态内存
- 多处理器/多核协同、内存保护
- 信号量、通用消息队列(只提供事件标志和 SPSC 环形缓冲)
