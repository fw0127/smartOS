# 附录 A 平台适配示例

> 本附录**不是设计的一部分**,只用来说明 05 篇的平台契约足够抽象、可以映射到差异很大的环境上。
> 内核源码不会引用这里出现的任何名称。

## A.1 三类平台的映射

| 契约能力 | 主机虚拟时间平台(测试用) | 通用裸机 MCU | 宿主于 RTOS / 操作系统线程 |
|---|---|---|---|
| `TICK_BITS` / `TICKS_PER_SEC` | 64 / 1 000 000 | 计数器宽度 / 计数器频率 | 64 / 系统单调时钟分辨率 |
| `now` | 返回虚拟时间变量 | 读自由运行硬件计数器 | 读系统单调时钟 |
| `critical_enter / exit` | 空操作(单线程) | 保存并关闭中断 / 恢复 | 加锁 / 解锁互斥量(或挂起调度) |
| `wait_until` | 虚拟时间直接跳到 `deadline` | 忙等;或设置比较匹配后进入低功耗等待 | 带超时地等待条件变量 / 信号量 |
| `notify` | 空操作 | 空操作(中断本身会唤醒处理器) | 发送条件变量 / 信号量 |
| `health_signal` | 记录时刻,测试可断言 | 喂硬件看门狗 | 向外部监控进程报心跳,或空操作 |
| `halt` | 记录原因后跳回测试框架 | 进入死循环等待看门狗复位,或请求软件复位 | 记录日志后终止进程 / 线程 |
| 前置条件(内核之外) | 无 | 启动代码:栈、数据段、时钟、看门狗初始配置 | 创建承载调度器的线程 |

## A.2 选择时间源宽度与速率

可比较的最大间隔 = 2^(TICK_BITS−1) / TICKS_PER_SEC。选择原则:

- 该间隔 ≥ 2 × max(最长周期, 最长存活窗口, 最长闹钟);
- 分辨率 1 / TICKS_PER_SEC ≤ 最小单步预算 / 10。

| 宽度 | 速率 | 分辨率 | 最大可比较间隔 | 适用 |
|---|---|---|---|---|
| 16 位 | 1 kHz | 1 ms | 约 32 s | 极小系统,不做执行时间监控 |
| 32 位 | 1 MHz | 1 µs | 约 35 min | 大多数 MCU 系统的推荐值 |
| 32 位 | 100 MHz | 10 ns | 约 21 s | 高频计数器,周期较短的系统 |
| 64 位 | 任意 | — | 实际不受限 | 主机、宿主于操作系统 |

如果硬件计数器很快但周期较长,平台可以读取计数器的分频视图或移位值,用分辨率换取范围——这完全是平台内部的事,内核不感知。

## A.3 参考固件所在平台的映射(仅作对照)

01 篇分析的原固件运行在一款多核 MCU 上。若把 smartOs 运行在该平台,映射如下:

| 契约能力 | 对应的平台资源 |
|---|---|
| 时间源 | 片上系统定时器的分频视图(原固件中已有读取函数) |
| 互斥区 | 关/恢复全局中断 |
| 等待 | 第一版忙等;以后用定时器比较中断 + 处理器等待指令 |
| 健康信号 | 服务 CPU 看门狗 |
| 安全停机 | 关闭对外通信输出 → 死循环等看门狗复位 |
| 前置条件 | 原固件启动代码中的栈/上下文区初始化与看门狗解锁序列 |

这一映射全部位于 `platform/<target>/` 目录内,内核源码保持不变。
